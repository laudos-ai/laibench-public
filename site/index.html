02 — HOW IT SCORES
01

Hard critical-finding veto

A missed or fabricated critical finding caps the score and forces FAIL — regardless of how polished the rest of the report reads.

02

No prose / aesthetic axis

No standalone style, fluency or "communication quality" dimension. The only discourse signals are minor, non-gating, fallback-only.

03

Conservative combination

The combined dimension score is MIN(deterministic, judge): an optional LLM judge can lower a score but never inflate it past the gate.

04

Tamper-resistant numbers

Every run is re-scored through the gated combiner; a relabeled critical-miss is rejected before it reaches the leaderboard. scoringHash + suiteHash provenance.

Gates that work without an answer key new in 3.11.0

C09Input critical findings preserved. Present, affirmed and on the same side. Side must be stated for pneumothorax, fractures, bleeds, torsion and stroke; a contradicted side always fails.critical
C10No critical finding beyond the input. Neither a new critical nor one moved to the other side. Recommendations and differentials are not counted.critical
Q16Abnormal findings reflected. Paraphrase-tolerant and polarity-aware; each missing finding costs separately.major
Q17No unsupported normalcy. An abnormal study cannot be reported as normal.critical

C09 and C10 recognize criticals from a fixed, versioned vocabulary (pneumothorax, hemorrhage, pulmonary embolism, stroke, free air, dissection, obstruction, fracture, cord compression, torsion and others, in English and Portuguese); a critical phrased outside it is not caught. The report title and Technique section are excluded because they restate the exam. Negation is clause- and list-scoped: “No effusion, consolidation, or pneumothorax” denies every item.

Dimensions: CRIT 30% · QUAL 25% · TERM 20% · GUIDE 15% · RAG 10%, with hard failure gates. LAIBench is a technical benchmark framework — not a medical device, not regulatory approval, not clinical validation.

    Reproduce it

    Clone, test, and regenerate the ladder and the provenance manifest yourself.

    git clone https://github.com/laudos-ai/laibench-public
cd laibench-public && npm ci
npm test && npm run ladder
npm run bench -- provenance --suite suites/lite-public.en-US.json --out provenance.json

    Submit a system

    Any agent that reads a JSON job on stdin and writes report HTML to stdout can be benchmarked, no SDK required. Frozen predictions are scored the same way and cannot self-report latency or retrieval.

    For the gated controlled evaluation, write to research@laudos.ai.

    npm run bench -- suite \
  --suite suites/lite-public.en-US.json \
  --provider command --cmd "node path/to/your-agent.mjs" \
  --run-name my-agent --track agent \
  --entity-name "My Lab" --entity-type org --system-type product-agent \
  --out runs/my-agent.json
