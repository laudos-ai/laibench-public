    Passing checks

    Make the report worse, one error at a time. The score should follow.

    For each of the 49 public cases we take a faithful reference report and inject exactly one error, from a changed measurement up to inventing a critical finding. Every version is scored against the original case. No answer keys are needed: the input findings are the evidence.

    Leaderboard

    Two governance tiers that are never mixed: a gated, first-party controlled evaluation, and a public smoke test of open models on synthetic cases that is a diagnostic, not a ranking. Benchmark cards cover case source, leakage risk and adjudication status.

    How a report is scored

    Deterministic checks first, an optional judge that can only lower a score, and gates that no amount of good writing can get past.

    1. 1

      Sanitize

      Only <center>, <b>, <br> survive. Scripts and markup injected to sway a judge are stripped.

    2. 2

      Deterministic checks

      Around 40 checks across five clinical dimensions: sections, terminology, coverage, laterality, measurements.

    3. 3

      Source-anchored gates

      Every critical in the input must survive with the same polarity and side; nothing critical may be invented.

    4. 4

      Optional judge, then MIN

      A pinned LLM judge can be added. Each dimension keeps the lower of the two scores, so the judge can never inflate one.

    5. 5

      Anti-compensation

      Perfect terminology and coverage cannot lift a clinically weak report into PASS.

    6. 6

      Critical veto

      Any failed critical check caps the case at 59.9 and forces FAIL. Every published number is re-derived through this gate.

    Five weighted dimensions, no prose axis

    CRIT 30%
    QUAL 25%
    TERM 20%
    GUIDE 15%
    RAG 10%
    CRIT
    Critical findings preserved, never denied, never invented.
    QUAL
    Findings preserved, no hallucination, a real impression.
    TERM
    Report language, modality vocabulary, section contract.
    GUIDE
    Anatomical and guideline coverage for the exam.
    RAG
    Evidence fidelity: title, laterality, levels, measurements, order.

    Gates that work without an answer key

    C09Input critical findings preserved. Present, affirmed and on the same side. Side must be stated for pneumothorax, fractures, bleeds, torsion and stroke; a contradicted side always fails.critical
    C10No critical finding beyond the input. Neither a new critical nor one moved to the other side. Recommendations and differentials are not counted.critical
    Q16Abnormal findings reflected. Paraphrase-tolerant, polarity-aware; each missing finding costs separately.major
    Q17No unsupported normalcy. An abnormal study cannot be reported as normal.critical

    The report title and Technique section are excluded from these gates because they restate the exam, which often names the clinical question. Negation is clause- and list-scoped: “No effusion, consolidation, or pneumothorax” denies every item.

    Form never rescues substance

    A missed or fabricated critical finding is a hard veto, not a deduction. There is no style, fluency or “communication” dimension.

    Conservative by construction

    The combined score per dimension is MIN(deterministic, judge). A judge can catch what rules miss; it cannot forgive what they catch.

    Tamper-resistant numbers

    Every loaded run is re-scored through the gated combiner. A run whose stored verdict disagrees with the re-derived one is rejected.

    Pinned provenance

    A scoringHash over every gate-deciding source file and a cases-only suiteHash pin exactly what produced each number.

    LAIBench is a technical benchmark framework. It is not a medical device, not regulatory approval and not clinical validation, and it evaluates reporting from text evidence, not image interpretation.

    The 49 public cases

    Synthetic, input-only demonstration cases: normals, critical findings, and traps for negation, laterality, measurements and hallucination. They are open so anyone can reproduce the harness; they are not clinically reviewed. Choose one to score it above.

    Reproduce it

    Clone, test, and regenerate the ladder and the provenance manifest yourself.

    git clone https://github.com/laudos-ai/laibench-public
cd laibench-public && npm ci
npm test && npm run ladder
npm run bench -- provenance --suite suites/lite-public.en-US.json --out provenance.json

    Submit a system

    Any agent that reads a JSON job on stdin and writes report HTML to stdout can be benchmarked, no SDK required. Frozen predictions are scored the same way and cannot self-report latency or retrieval.

    For the gated controlled evaluation, write to research@laudos.ai.

    npm run bench -- suite \
  --suite suites/lite-public.en-US.json \
  --provider command --cmd "node path/to/your-agent.mjs" \
  --run-name my-agent --track agent \
  --entity-name "My Lab" --entity-type org --system-type product-agent \
  --out runs/my-agent.json
